# 02 — Mechanical test metrics (slice 2)

Generated by `test-audit/scripts/test-metrics.mjs` over `git ls-files '*.test.ts' '*.test.tsx'`
(1,974 files). Duration data comes from a single full `yarn vitest run --reporter=json`
pass, joined per file by `test-audit/scripts/durations.mjs` into
`test-audit/raw/durations.csv`.

Counting conventions:

- `cases`: `it(`/`test(` call sites incl. `.each`/`.skip`/`.only`/`.concurrent` variants,
  counted on comment-and-string-stripped source, so prose and fixtures do not inflate counts.
- `expects`: `expect(` call sites on stripped source. Includes `expect.soft`/`vi.expect` style usage.
- `viMocks`: `vi.mock(` call sites (module mocks).
- `viFnSpies`: `vi.fn(` + `vi.spyOn(` call sites.
- `guard`: file reads source text at runtime — `readFileSync`/`readFile` of a
  `.ts`/`.tsx`/`.css`/`.mjs`/`.json` path, or directory walking plus source-extension literals.
- Tiers, first match wins: `route` = `app/**/route.test.ts(x)`; then `pg` = listed in the
  CI `test-pg` job; `component` = `.tsx` test under `lib/components` or `app`; `db` = `lib/database`;
  `service` = `lib/services`; else `other`.
- `importsUnderTest`: relative (`./`, `../`) and `@/` imports, minus test infrastructure
  (vitest, testing-library, mocks, fixtures). Note: `app/globals.*.test.ts` etc. import
  only CSS or nothing importable, and pure-linter-guard tests import only the lint plugin.

## Caveats

- Counts are regex-based on comment-stripped source; a `vi.fn(` inside a string
  literal is excluded by the stripper, but dynamic aliasing (`const t = vi.fn`)
  counts once per call site, not per invocation.
- `importsUnderTest` excludes specifiers containing vitest/testing-library/mock/fixture
  tokens; a source file genuinely named with those tokens would be missed (none found in spot checks).
- The vitest JSON run reported `success: false` solely due to the 2 zip-format tests above;
  every other file passed.
